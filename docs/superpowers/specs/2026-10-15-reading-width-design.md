# Reading Width — плагин Obsidian: регулируемая ширина полосы чтения

Дата: 2026-10-15. Статус: спека на ревью.

## Зачем

В Obsidian ширина текста переключается тумблером «Ширина строки читаемая»: узкая полоса (700 px) или весь
экран. Нужна промежуточная ширина, которую можно менять на ходу. Плагин отдельный и не привязан к хранилищу:
ставится в любое.

## Что делает

Переопределяет CSS-переменную Obsidian `--file-line-width` (в стандартной теме по умолчанию `700px`) на
`body` главного окна и всплывающих окон. Тумблер «Ширина строки читаемая» остаётся как есть: при включённом
берёт новое значение, при выключенном текст идёт на весь экран и плагин на него не влияет.

Проверено 2026-10-15 в песочнице: `getComputedStyle(document.body).getPropertyValue('--file-line-width')` →
`700px`, `app.vault.getConfig('readableLineLength')` → `true`.

## Поведение

| Что | Как |
|---|---|
| Значение | ширина в px, целое, диапазон 400–2400, шаг ползунка 10 |
| «По умолчанию» | переменная снимается с `body`, Obsidian возвращается к своим 700 px |
| Хранение | `data.json` плагина, одно значение на всё хранилище |
| Строка состояния | пункт «Ширина 700» (или «Ширина стандарт»); клик открывает всплывающее меню с ползунком и кнопкой «По умолчанию» |
| Ползунок | значение применяется сразу при движении; запись в `data.json` с задержкой 300 мс |
| Команды | «Шире», «Уже» (шаг из настроек, по умолчанию 50), «Сбросить»; горячие клавиши назначает пользователь |
| Настройки | ползунок, поле с точным числом, шаг для команд «Шире/Уже» |
| Всплывающие окна | значение применяется и к ним (`workspace.on('window-open')`) |
| Выключение плагина | переменная снимается со всех окон, ширина возвращается к стандарту |

## Структура

```
obsidian-reading-width/
  manifest.json            id: reading-width, isDesktopOnly: false
  package.json, tsconfig.json, esbuild.config.mjs, vitest.config.ts
  src/width.ts             чистая логика: clamp, шаг, подпись, значение переменной
  src/main.ts              плагин: загрузка/сохранение, применение к окнам, команды, статус
  src/popover.ts           меню с ползунком из строки состояния
  src/settings.ts          вкладка настроек
  styles.css               оформление меню
  scripts/deploy.mjs       копирование main.js, manifest.json, styles.css в <vault>/.obsidian/plugins/reading-width
  test/width.test.ts       тесты чистой логики
```

Границы: `width.ts` ничего не знает про Obsidian и тестируется отдельно; `main.ts` единственный, кто трогает
DOM окон; `popover.ts` и `settings.ts` только читают и меняют значение через методы плагина.

## Интерфейс плагина (внутренний)

- `getWidth(): number | null` — `null` = по умолчанию.
- `setWidth(px: number | null, opts?: { persist?: boolean })` — ограничивает диапазоном, применяет ко всем
  окнам, обновляет строку состояния, при `persist` пишет в `data.json`.
- `step(dir: 1 | -1)` — сдвиг на шаг из настроек.

## Ошибки и края

- Пустой или повреждённый `data.json`: значение `null`, плагин работает как без настроек.
- Значение вне 400–2400 в `data.json`: ограничивается при загрузке.
- Всплывающее окно закрыто: ничего не делаем, переменная живёт на `body` окна.
- Тема, которая не читает `--file-line-width`: в этой версии не поддерживается, видно по тому, что ползунок
  ничего не двигает. Запасной вариант (своя `<style>` с `max-width` на `.markdown-preview-sizer`/`.cm-sizer`)
  в спеку не входит.

## Тесты и проверка

- `vitest`: clamp границ, шаг вверх/вниз у границ, сброс, подпись («Ширина 700» / «Ширина стандарт»),
  чтение битого значения.
- `tsc --noEmit` чистый.
- Руками в песочнице TJCC на широком окне: ползунок двигает полосу сразу, команды «Шире/Уже/Сбросить»
  работают, после перезапуска плагина значение на месте, после выключения плагина полоса стандартная.
  Снимок до и после.

## Вне рамок

Ширина по заметкам, режим в процентах, мобильный интерфейс, публикация в каталог плагинов.

## Установка

`npm run deploy -- <путь к хранилищу>` для любого хранилища. Сначала песочница TJCC
(`~/Vaults/TJCC/.dev/sandbox`), в рабочие хранилища только по слову Jw Ujl.
